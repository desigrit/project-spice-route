Push in four moves

  1. 1ReviewPreview changes; close Codex.
  2. 2CaptureStage SQLite copies; select rows and files.
  3. 3PackHash, compress and reuse file objects.
  4. 4PublishVerify objects, then write the manifest.

Pull in four moves

  1. 1DiscoverFind a visible complete manifest.
  2. 2VerifyRead every required object and hash.
  3. 3ReconcileReview conflicts and map local roots.
  4. 4RestoreBack up, merge, then verify Codex and files.

Why the database layout matters

1
Selection. Spice Route extracts only the rows for included chats and projects.
2
Merge. Pull adds or updates those rows while preserving unrelated local chats and local policy fields.
3
Compatibility. A changed table or column can make that selective merge unsafe, so untested layouts block writes.

In older supported Codex layouts, thread_artifacts is used where newer layouts use thread_attachments. Spice Route translates that known difference. A transcript file alone is not the complete chat.

Projectless chats

Included by default, including archived chats. Each selected chat carries its database history, rollout, linked attachments and associated files inside the configured projectless workspace root. You can exclude an individual chat.

Local to each computer

Codex credentials, machine identity, global settings, skills, plugins, automations and destination folder paths are not imported from another device. Existing unrelated local chats remain.

Full project includes sensitive working files by default, but skips recognized dependency, cache and build folders unless enabled. Changing a selection does not erase older cloud snapshots. History-only projects may need an empty mapped folder on the destination.
